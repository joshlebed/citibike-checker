# agent notes for citibike-checker

Unlike the sibling repos under `~/code/`, this one does **not** run on a
homelab host. It's an AWS SAM stack in `us-east-1` plus a static GitHub
Pages frontend. No Tailscale, no SSH-to-host deploy cycle, no
`make verify`.

## pushing to main is a production deploy

`.github/workflows/deploy.yml` runs `pytest` then `sam build && sam deploy`
on every push to `main`. There is no staging environment and no manual
approval step. Validate locally first:

```bash
uv run pytest tests/ -v
uv run scripts/test_mock.py -v
```

`scripts/test_local.py` hits the real GBFS feeds and expects a
`josh-profiles.json` that isn't in the repo — it won't work in a fresh
clone.

## the reporting logic is the product

Everything else is plumbing. The rules live in `src/lambda_app/handler.py`
and are keyed off one constant, `LOW_AVAILABILITY_THRESHOLD = 3`:

- **Docks** — `_select_dock_lines()` walks entries (primaries first, then
  backups), skips stations with 0 docks, and stops after the first entry
  with **more than** the threshold. Groups collapse to their total when the
  first member has docks, expand member-by-member when it doesn't.
- **Bikes** — same shape, but *accumulates* e-bikes across entries and
  stops at `>=` the threshold, then falls back to classic bikes if it never
  got there.

The two differ on purpose: you can only park at one station, but you'll
take a bike from wherever. Don't "unify" them without deciding which
semantics you actually want.

**Keep the English and JSON formatters in sync.** Docks share
`_select_dock_lines()`, so a change there lands in both. The bikes path
still duplicates its selection loop across `_format_bikes_english` and
`_format_bikes_json` — edit both, or factor it out the way docks does.

## config is per-request, not server-side

The Lambda is stateless: every request carries its own `profile`. A user's
config lives inside their Siri Shortcut. Consequences:

- Changing reporting behavior means changing code and deploying — no
  config shape can express "stop early" or retune the threshold.
- `docs/index.html` (the station picker) is the config generator. If you
  add a request field, the picker has to emit it or nobody will ever set
  it.
- Nothing migrates. Old Shortcuts keep POSTing their existing payloads
  forever, so request-format changes must stay backward compatible.

## don't hand-edit `data/stations.json`

It's regenerated by `./scripts/refresh_stations.sh` from the GBFS feed.
`docs/stations.json` (what the picker loads) is built from it by
`scripts/build_stations_web.py`.

## cost posture

The API is public and unauthenticated. Bounds are a 5 req/s API Gateway
stage throttle, an account-wide Lambda concurrency cap of 10, profile-size
limits in the handler, and a $5 monthly budget alarm (notification-only).
The WAF was deliberately removed — it was ~$6/mo flat, more than the rest
of the stack combined. See the decision log in the README before adding
anything with a fixed monthly fee.

## `total_primary` in the docks JSON is informational only

It's the sum across all primary entries, but nothing acts on it — the
selection walk ignores it. So `total_primary: 37` alongside
`showing_backups: true` is reachable (first primary full, walk stops before
reaching the healthy one). Don't reintroduce the old
`total_primary <= 3 → showing backups` inference on the consumer side.

## if the deploy fails with "web identity token could not be validated"

The GitHub OIDC provider is missing from the AWS account. Check
**IAM → Identity providers** in the console — `token.actions.githubusercontent.com`
should be listed alongside the AWS SSO SAML provider.

**Do not trust CloudFormation here.** The `citibike-github-oidc` stack keeps
reporting `CREATE_COMPLETE` for both the provider and the role even when the
provider has been deleted out-of-band; the stack is drifted and has no way to
notice. This happened between 2026-04-22 and 2026-08-20 and cost a long
debugging detour — `describe-stack-resources` said the provider existed while
IAM said otherwise.

Recreate it (console: Add provider → OpenID Connect, or CloudShell):

```bash
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1 \
                    1c58a3a8518e8759bf075b76b750d4f2df264fcd
```

The ARN derives from the URL, so a recreated provider gets the identical ARN
and the existing role's trust policy matches again with no edits. Then
`gh workflow run deploy.yml` — no new commit needed.

Note the error message is misleading: a *missing* provider produces
"could not be validated", not "No OpenIDConnect provider found". A `sub`/`aud`
mismatch in the trust policy would produce `AccessDenied` instead.

## getting AWS credentials for this account

The account (`590184113718`) has **IAM Identity Center** configured, so
`aws configure sso` is the right path — not IAM access keys.

Avoid root access keys specifically: session tokens derived from root
credentials **cannot call IAM APIs** without MFA, which makes them useless for
exactly the OIDC debugging above (STS and CloudFormation calls still work,
which makes the failure confusing). CloudShell is unavailable to the root user
but works for IAM/Identity Center sign-ins, and needs no local credentials at
all.
